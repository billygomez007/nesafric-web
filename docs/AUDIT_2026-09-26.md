## Remaining items

Two items are open (PARTIAL). One is an intentional limitation, and two were observed once in
the browser.

| Item | Status | Severity | Blocks production |
| --- | --- | --- | --- |
| Paused listings republish without re-review | PARTIAL (policy decision) | Medium (moderation) | No |
| Voice media-sweep secret is optional | PARTIAL | Low | No; set the secret in production |
| Replaced logo cached for up to an hour | Intentional limitation | Info | No |
| Phase 22B voice test timeout | Observed once | Info | No |
| Test-data contamination between browser runs | Observed, not a product defect | None | No |

### Paused listings republish without re-review — PARTIAL (policy decision)

- **Issue:** a verified marketplace listing can be paused, edited (title, description, photos,
  price) and republished by an OWNER or ADMIN without another NesAfric review.
- **Root cause:** `updateListing` allows edits while PAUSED, and republishing a VERIFIED listing
  from PAUSED is an owner action. Both are deliberate in the current code and its tests.
- **Why not fixed:** this changes the moderation policy rather than fixing a defect. It needs a
  product decision.
- **Affected:** marketplace buyers, who may see content that has changed since it was verified.
- **Recommended fix:** when a PAUSED marketplace listing's public content changes, require
  `PENDING_REVIEW` before it can be republished. Verification of listing authority can stay as
  it is.

### Voice media-sweep secret is optional — PARTIAL

- **Issue:** `POST /api/voice/media-stream/sweep` enforces `VOICE_MEDIA_SWEEP_SECRET` only when
  the variable is set.
- **Why not fixed:** this "enforced only when set" behaviour is documented and deliberate. The
  endpoint only cleans up orphaned streams, so it exposes no data.
- **Recommended fix:** set `VOICE_MEDIA_SWEEP_SECRET` in production. Optionally, make the
  endpoint fail closed when `NODE_ENV=production`.

### Replaced logo cached for up to an hour — intentional limitation

A replaced logo URL returns 404 at once (its storage object is archived). Browsers that already
fetched it may keep showing it for up to one hour, because `/api/public/media` sends
`Cache-Control: max-age=3600`. New pages always use the new URL, so no change is needed.

### Phase 22B voice test timeout — observed once

`phase22b-realtime-voice` hit its 5-second timeout once, in an early full-suite run, while the
machine was also building. Since then it has passed in every run: 20 of 20 in isolation, and 3
more full-suite runs. It was not made deterministic because it could not be reproduced. If it
recurs, look at the STT/TTS mock latency in that suite.

### Test-data contamination between browser runs — observed, not a product defect

During browser runs, leftover data from an earlier run caused misleading results. The journey
scripts now reset the disposable database before each run.

## New or changed configuration

- `VOICE_PROVIDER_API_SECRET` is **required** for the voice call API; see `.env.example`.
  Without it those endpoints return 503.
- The fresh-database bootstrap needs `psql` (unchanged) and now fails on any schema drift.
